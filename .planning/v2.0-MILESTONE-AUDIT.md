# Milestone v2.0 "Persona Realism" — Audit

Audited 2026-08-28 at `ea783c0f`. 12 plans across 2 phases, all with SUMMARY.md, all pushed.

## The headline

**The work is done and wired; the verification paperwork is not.** Those are two different
statements and this audit returns `gaps_found` on the second, not the first.

The integration checker independently traced 7 of 8 requirements end-to-end in code and found
them wired. Separately, the requirements matrix scores 0 of 8 as formally satisfied, because
**neither v2.0 phase has a VERIFICATION.md** and 9 of 12 SUMMARYs omit
`requirements-completed`. Under the workflow's status matrix, a missing verification plus missing
frontmatter is `unsatisfied` regardless of whether the feature exists.

So the 5 "unsatisfied" requirements below are not five broken features. Four of them
(PERS-01, STORY-01, STORY-02, STORY-03) were verified working by direct code reading during this
audit. That is an artifact gap, and it is partly self-inflicted: the summaries written during
this milestone used `tags`/`key-files` frontmatter and never `requirements-completed`.

## Two real defects, though

Both were reported by the integration checker and both re-verified independently here.

### INT-01 — the UK's real GBD pyramids are unreachable (blocker)

04-03 emits the UK's 41 regions as `nuts2:UKC1`, `nuts2:UKD1`, … 04-05 assigns UK cells
`adm1:GBR-2001`, … because it derives its NUTS-preferring country set from
`subnational-cdr.json`'s `meta.nutsCountriesIso3`, which does not contain `GBR` — the UK stopped
reporting to Eurostat. Measured on the shipped files: **0 of 41 GBR keys join**. All 226 assigned
UK cells fall back to WorldPop-derived instead of the GBD-measured tier, silently, with no
diagnostic. That is **1.09% of world expected deaths**, and `04-04-SUMMARY.md` line 81 states the
UK uses real GBD weights — which is false as shipped.

Italy and Poland do work, so this is specific to the UK, and the fix is small: add `GBR` to the
NUTS-preferring set, or key the join on country rather than `geo:key`. What makes it worth a
blocker is not the size but that a wrong claim is recorded as verified.

### INT-02 — 04-06's entire artifact is dead (blocker)

`data/eurostat-regional.json` is 1.77 MB, committed, and read by nothing. The only other
occurrences in the tree are three prose comments. 04-07 imports Python helpers from
`pipeline/sources/eurostat.py` but never the JSON. 04-06 is assigned PERS-01 and PERS-02 and, as
shipped, contributes to neither.

This does not mean 04-06 was wasted — the Eurostat *module* is used by 04-07 — but the plan's
declared deliverable has no consumer, and its SUMMARY's claim that the file is "a build-time
validation input, like `observed-regional-age-sex.json`" is not true of the shipped tree.

closer to a single corrective plan, alongside the artifact backfill:

1. Add `GBR` to the NUTS-preferring set (or key the tier-1 join by country), rebuild
   `age-sex-cells.json`, and add the missing diagnostic for tier-1 keys that win no cell.
2. Decide `eurostat-regional.json`'s fate: wire it into `build-age-sex-cells.ts` as the European
   validation set 04-06 intended, or delete it and correct the SUMMARY.
3. Backfill `04-VERIFICATION.md` and `05-VERIFICATION.md`, add `requirements-completed` to the 9
   SUMMARYs missing it, and refresh the 4 stale traceability rows.

Then re-run this audit; on the evidence above it should pass.
